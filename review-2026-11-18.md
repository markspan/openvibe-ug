# Review of the UG fork against upstream (4891073)

> **Status, 18 November 2026.** What this review found as it stood at commit 8551865. Since then:
> - **Fixed in 2a981a5** (UG.md 2.41): findings 1 to 5 and 9, and the backslash part of 8.
> - **Fixed in 2a981a5** (UG.md 2.42): the low findings of section 3, and the upstream IPv6 overrun of section 4.
> - **Left as they are, by choice:** finding 6 (the drift thread), 7 (the BrainVision writer (UG) as a copy of the
>   Gipsa writer) and the repeated sentences of 8; and, with their reasons in UG.md 2.42, the player loop's 1 ms
>   wake-up, the English summaries in `CharmeleonMontage`, the console log and the stimulation delay.
> - **Not addressed:** the Qt install rule of section 4, which is upstream's.

All code changes of the fork were read: 327 files, about 35,000 lines added and 4,300 removed, of which about
18,000 lines are scenario XML and 3,000 a test input. The rest, about 18,000 lines in some 150 files, is
reviewed below, area by area. Scenario XML, `*.dox-part`, UG.md, montages.md and speller.md were checked only where
code depends on them.

## In short

The fork is in good shape on the things that are hard to retrofit: thread hand-offs are locked and documented,
the timing logic (block stamps, steady triggers, stimulation delay) is small, pure and tested, and every change is
explained where it is made and in UG.md. No hidden hacks were found of the "works by accident" kind.

Where it falls short of the brief is **duplication**: three pieces of logic exist twice, in places the fork itself
added. And one change **breaks the Linux and macOS builds**, which upstream's CI runs.

## 1. High

### 1.1 The acquisition server no longer compiles on Linux and macOS

`extras/applications/platform/acquisition-server/ui/AcquisitionController.cpp` includes `<QWinEventNotifier>` and
`<Windows.h>` without a guard, and uses `QWinEventNotifier` and `HANDLE` for the Charmeleon watcher. Upstream's CI
builds Linux and macOS (`.gitlab/build.yml`); the fork's server fails there. `Charmeleon.cpp` is guarded already.

**Fix:** guard the watcher with `#ifdef _WIN32`, or better, move it into `Charmeleon.cpp` behind a platform-neutral
"call me when it closes" function, so the controller has no Windows types at all.

### 1.2 Montage handling is duplicated in the TMSi and eego drivers

`applyMontage()`, `charmeleonMontage()`, `takeOverCharmeleonMontage()`, `onMontageChanged()`, `report()` and
`failInit()` are near-identical in both drivers (about 90 lines each), as are the members `m_paramMontage`,
`m_montageNote`, `m_lastError`, `m_configuredNames`/`m_configuredLocks`, the "record only the named channels,
restore the full list in unInit()" flow, and the backlog estimate in `takeDeviceBuffer()`. They differ only in the
channel kinds, TMSi's assumed layout, the "device is open" test and the log prefix.

**Fix:** a `MontageDriver : AbstractDriver` base (in the abstractions library, next to `CharmeleonMontage`) that
owns all of this, with three small hooks: the channel kinds, whether the layout is assumed, and the device name of a
channel. It is also the natural home for the Charmeleon virtuals of 9.

### 1.3 The display panel is built twice

- **Panel parameters.** `CSignalDisplayController` and `CLSLDisplayController` each build Display Mode, Auto vertical
  scale, Time Scale, Vertical Scale, Multiview, Colour per channel, Trace shading and both rulers by hand: nine
  parameters with their names, help texts, ranges and enable rules. The help texts already differ (Multiview). The
  box settings are shared (`addDisplaySettings()`); the panel is not.
- **QML.** `SignalDisplay.qml` and `LSLDisplay.qml` repeat the same 40-line block: amplitude ruler, channel gutter,
  `SignalTrace` with the antialiasing layer (4 samples, the 8192 px limit), sweep cursor, stimulation overlay.
- **Per-page rescale.** Both controllers carry the "work the scale out once per page" logic, each with its own
  `FIRST_PAGE_RESCALE_MS = 500`, and their first-page tests already differ.

**Fix:** one panel builder bound to an `SDisplaySettings&` and a change callback; one `TracePanel.qml`; one small
`PageRescaler` (or a method on `CSignalTraceItem`).

## 2. Medium

### 2.1 The montage reaches the writer through global configuration tokens (finding 4)

The Acquisition client sets `AcquisitionServer_Montage` and `AcquisitionServer_ElectrodePositions` as
configuration tokens, and the BrainVision writer (UG) reads them. This is state shared by every box in the player,
invisible in the scenario: two acquisition clients overwrite each other, and a writer fed from a file reader picks up
whatever the last client set.

OpenViBE has a stream made for this, `OV_TypeId_ChannelLocalisation`, with encoder and decoder in the toolkit, used by
the topographic maps. An extra output on the client and an optional input on the writer would make the route
explicit, typed and per-scenario.

### 2.2 Port in use: probe instead of exclusive bind (finding 5)

`CServer::somethingListensOn()` probes the port with a loopback connect (up to 300 ms) because the server sets
`SO_REUSEADDR`, which on Windows lets two servers share a port. The standard fix is to set `SO_EXCLUSIVEADDRUSE`
instead on Windows (keep `SO_REUSEADDR` elsewhere); `bind()` then fails with `WSAEADDRINUSE`. That removes the probe,
its race between two servers starting together, and its delay.

### 2.3 Drift still computed (finding 6)

The drift display and its settings were replaced by the buffer levels, but `Acquisition` still creates a
`DriftCalculator` and runs the drift thread on every acquisition, and `Acquisition::drift()` has no caller left.
Either remove the thread and calculator, or show the drift again.

### 2.4 BrainVision writer (UG) copies the Gipsa writer (finding 7)

204 of the Gipsa writer's 231 code lines (.cpp) and 83 of 107 (.h) reappear in the UG writer. Leaving upstream's box
unchanged is deliberate (UG.md 2.9), but the shared part (header, markers, data, binary formats) could be one base
class or helper both use, so that a fix to the format lands once.

### 2.5 Error messages: wording repeated per call site (finding 8)

About 130 error messages were rewritten (UG.md 2.23). The same long sentences are pasted at several sites: in
`ovkCConfigurationManager.cpp`, "holds a token that is not written correctly. A token reads ${Name}..." appears four
times, "a token starts with the prefix ... which we regret to say we do not know" four times, and three more twice,
because the file has two near-identical expansion functions. In the file boxes "Paths need forward slashes, as a
backslash is lost on the way to a box" appears three times or more. Each message belongs in one function or constant.

The backslash message explains an upstream defect instead of fixing it. The fork already fixed the picker
(`ParameterPathObject::decode()` gives forward slashes); a typed or old setting still loses its backslashes.
Normalising `\` to `/` for Filename and Foldername settings before token expansion would remove the cause.

The courteous suffixes ("Would you be so very kind as to check it? Thank you for your patience.", "Our deepest
regrets") lengthen every error and vary from site to site. That is a choice, but central phrases would at least
keep it consistent.

### 2.6 Charmeleon on the generic driver interface (finding 9)

`AbstractDriver` gained `usesCharmeleonForImpedance()`, `charmeleonArguments()`, `charmeleonMontage()`,
`montageSetting()` and `takeOverCharmeleonMontage()`, and `Acquisition` mirrors them with seven pass-through getters.
An external tool's concepts now sit in every driver's interface. With the base class of 1.2, the server can ask
once for an optional `CharmeleonSupport*` (null for drivers without it).

## 3. Low, per area

**Acquisition server core**
- `Acquisition.cpp` `#pragma comment(lib, "Avrt.lib")`, and `ovkCKernelContext.cpp` the same for Shell32/Ole32:
  link in CMake instead.
- `AbstractWriter::writeSamples()` saves the pending stimulation count, overwrites it with the due count for
  `send()`, and restores it, because upstream uses the message's `stimCount` both as wire field and as counter.
  A separate member for the pending count makes it straightforward.
- `Acquisition::read()` sleeps 1 ms after an empty read shorter than 500 µs, and the TMSi driver also sleeps 1 ms on
  an empty read: two layers own one policy.
- `describeChannels()` applies the montage a second time, by name, for the clients; the driver already knows the
  positions. Could diverge from the driver's rules.
- `ovMsgSerializer.h`: the comment says only OV_MSG_SAMPLES allocates; the config message now allocates
  `channelNames` too.
- `AcquisitionController::buffers()` is a `QVariantMap` of ten string keys; a `Q_GADGET` would type them. The note
  level crosses C++/QML as the strings "info"/"warning"/"error".
- QML uses `DS.Theme.cpuUsageColors["high"/"medium"]` as error and warning colours.

**Charmeleon**
- `Charmeleon::closeAll()` runs on the UI thread at Play: up to 3 s of `Sleep(200)` polling, plus up to 1 s per
  terminated process. `WaitForMultipleObjects` on the handles, or a worker thread, avoids the freeze.
- `Charmeleon::launch()` quotes arguments without escaping; an argument ending in a backslash or containing a quote
  breaks the command line.
- Small helpers copied between files: `trim()` (3 copies), `toUtf8()` and `isFile()` (2 each).
- `applyCharmeleonMontageSetting()` also writes the kept copy (documented); the write is not atomic.

**Drivers**
- `CDriverEEGO::start()` builds a `std::regex` for a substring test (`type.find("EE511")` does).
- New files still carry per-line `// UG fork` tags in places, though UG.md says a new file is tagged once.

**Designer**
- `PlayerBridge::looping()` now sleeps 1 ms between rounds (was 50): up to 1000 wake-ups a second while playing.
  Waiting until the scheduler's next due time would keep the low latency without the spinning.
- `DesignerScenario::clickPort()` calls `stopLinkCreation()` on each of about eight exit paths; a scope guard says
  it once.
- `ConsoleLog` replaces upstream's `AttachConsole`: Designer started from a terminal no longer prints there.
  Deliberate (UG.md 2.17).

**Displays**
- `CLSLReader`: the colour of a text marker comes from `std::hash<std::string>`, which is not stable between runs;
  `uint64_t(int64_t(x))` is undefined for a NaN numeric marker.
- `StimulationDelay` holds stimulations at least one chunk (about 100 ms) behind the signal, by design, so late TCP
  tags get their own sample. Worth knowing for online use.

## 4. Upstream issues noticed (not the fork's)

- `CServer::initConnection()` puts a `SOCKADDR_IN6` into a 16-byte `struct sockaddr` (MSVC warning C4789, buffer
  overrun). Should be `sockaddr_storage`.
- The top-level install copies Qt's whole `bin` folder into `bin`, including Qt's own `designer.exe`, which has the
  same name as OpenViBE's Designer; the install order decides which one remains. It also ships Qt's tools and debug
  DLLs, which is most of the installer's 379 MB.

## 5. What is good

- Pure, testable cores with tests: `BlockStamps.h`, `SteadyTrigger.h`, `SampleBlocks.h`, `StimulationDelay.h`,
  `CharmeleonMontage`, `ovChannelInfo.h`, `SignalScaling.h`, `TraceShading.h`, `P300SpellerState`, the LSL
  recorder (checked against pyxdf and MATLAB).
- Threading: busy loops replaced by condition variables (circular buffer, control API), the restart and failure
  hand-off in the client under one mutex, driver state behind a mutex with a listener called outside it.
- Robustness fixes that upstream lacks: no samples dropped on a block-size change, network timeouts no longer close
  connections, upstream leaks of deserialized arrays fixed, socket closed when bind fails.
- Documentation: every change is explained at the place it is made, and in UG.md with files, behaviour and
  consequences.
